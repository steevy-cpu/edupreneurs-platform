# Jude-01 independent security review

**Request changes on PR #28.** The signed-session and lesson-publication boundaries held in the tested paths. The implementation does not yet meet its stated guarantees for prompt lifetime, maximum spend, accounting after a local failure, or reservation ownership across retries. Keep the router unregistered, the SQL outside production migrations, and live providers disabled.

## High severity

| ID | Observation and evidence | Minimal correction and regression gate |
| --- | --- | --- |
| J-01 · Completed learner prompts survive their requests | The factory-selected mock stores every complete `ModelRequest` in `self.calls`. After a normal answer returned and collection ran, an independent weak reference to the request remained live. A long-lived service therefore retains student text and lesson context across requests, with no size limit or learner erasure hook. The observed storage was process memory. [Factory mock](../../../services/api/src/edu_api/tutor/providers/mock.py) | Ship a non-recording mock by default. Keep counters or synthetic behavior indices in it and move request capture into an explicitly injected test spy. Require `test_factory_mock_drops_completed_request` to pass. [Regression](../../../tests/unit/tutor/test_independent_boundaries.py) |
| J-02 · A successful reservation can exceed the hard global ceiling | The service reserves from UTF-8 byte counts divided by three and omits message framing. The QA tariff charged one micro-USD per input token. A mock invoice differing by one framing token settled **1,736 micro-USD against a ceiling of 1,735**, with zero still reserved. PostgreSQL accounted for the supplied invoice correctly. The stock mock uses the same estimator for its invoice as the application uses for its hold. This experiment establishes that the advertised bound is unproven even with a one-token discrepancy. [Estimator](../../../services/api/src/edu_api/tutor/text.py) · [Settlement](../../../services/api/src/edu_api/tutor/service.py) | Before dispatch, require a provider-specific enforceable cost bound covering the serialized messages, framing, output and every allowed attempt. Refuse paid dispatch when that bound is unavailable. Keep actual invoices intact and surface discrepancies. Require `test_normal_provider_framing_fits_the_admitted_ceiling` and existing parallel-cap tests to pass together. [PostgreSQL regression](../../../tests/tutor_pg/test_independent_accounting.py) |
| J-03 · A completed provider call can be recorded as unsent | A mock returned a successful, metered completion. An injected local validator fault then raised an unexpected exception. The gateway had not recorded the attempt yet; the service released the hold at zero. The synthetic provider had completed exactly one call. This affects the ledger and the eligibility of the idempotency key for another attempt. [Gateway](../../../services/api/src/edu_api/tutor/gateway.py) · [Service](../../../services/api/src/edu_api/tutor/service.py) | Record dispatch and returned usage independently of parsing. If local validation fails, settle known usage once, or conservatively settle an unknown dispatched attempt. Reserve release for an established non-billable outcome. Require `test_completed_provider_call_remains_chargeable_if_local_validation_fails` to pass. [Regression](../../../tests/unit/tutor/test_independent_boundaries.py) |
| J-04 · A fresh PostgreSQL attempt reuses the previous lease ID | After one normal release, a permitted retry of the same learner/key returned the same reservation UUID. Settlement and release identify the active lease by learner and UUID. The SQL layer therefore cannot distinguish a delayed finalization for the old attempt from one for the new attempt. The in-memory store issues a fresh UUID. The independent test checked lease identity without altering another learner's data. [SQL reserve/settle/release](../../jude-01/sql/tutor_schema.sql) | Keep the logical idempotency key and issue a fresh lease identifier or generation on every new admission. Match that generation for all finalization and inspect the SQL outcome in the Python store. Require `test_each_admitted_attempt_has_a_fresh_lease` and a stale-finalizer no-op test before adopting the SQL. [PostgreSQL regression](../../../tests/tutor_pg/test_independent_accounting.py) |

## Boundaries that held, and their limits

- **Identity and lesson access.** The private test app used the normal token verifier. An answer for learner A incremented only A's status. A body naming A while signed in as B returned 422 and left B's usage unchanged. Both learners could read a published synthetic lesson. After its only current release was withdrawn, current and explicit-revision reads were refused for both. The baseline also exercised draft, unapproved, replaced and unknown revisions. The tutor queries lesson/question tables under transaction-local identity and RLS; it does not query another learner's attempts or progress. Its availability route reads the caller's counters. Access was tested at lookup time, without a claim about withdrawal during an already-running provider request. [Independent integration tests](../../../tests/integration/test_independent_jude_access.py) · [Lesson source](../../../services/api/src/edu_api/tutor/content.py) · [Transaction binding](../../../services/api/src/edu_api/db/session.py)
- **Accounting that reconciled.** The existing role, isolation, concurrency, duplicate-key, rounding and unknown-timeout cases passed. Independent checks found one terminal charge after concurrent expiry/settlement, preserved an existing hold after an out-of-range addition, and observed one settlement after client cancellation during settlement. Erasing a learner with a hold, then delivering a late settlement, kept personal rows absent and the anonymous charge intact. The unknown-usage amount is still subject to J-02. [Accounting checks](../../../tests/tutor_pg/test_independent_accounting.py)
- **Retry and price bounds.** The gateway builds a finite plan of one to four primary attempts plus at most one explicitly configured fallback. Defaults select no fallback; a higher input or output tariff requires separate opt-in. These controls passed the candidate tests. Per-request controls bound output tokens and attempts, while J-02 affects their conversion to a monetary guarantee. A SQL policy TTL can also differ from the duration validated by the Python settings. [Gateway](../../../services/api/src/edu_api/tutor/gateway.py) · [Provider tests](../../../tests/unit/tutor/test_gateway_and_providers.py)
- **Remaining lifecycle contracts.** Before connecting account deletion, enforce revocation and drain or fence admissions for that learner across erasure. SQL erasure scans existing reservations and deletes rows; it establishes no lasting account-admission fence. Retention purges finished request rows and with them their idempotency keys. Learner counters persist until erasure. Agree the retention and replay horizons, worker ownership and effective SQL TTL. For multi-model spending, the service persists total usage and the last attempt's model/price version; that row alone cannot reconstruct differently priced attempts. [Governance](../../../services/api/src/edu_api/tutor/governance.py) · [Ledger proposal](../../jude-01/sql/tutor_schema.sql)
- **Prompt, output and logging.** In the baseline, injected lesson text stayed in the untrusted data message; role separation, invalid JSON, unknown citation IDs, canary leakage, typed provider failures and log-marker checks passed. Issued IDs map server-side to supplied passages. This verifies reference provenance, not factual support for every answer or resistance to semantic prompt injection. Fixed replies selected by the deterministic danger screen made no model call. No conversation marker appeared in the tested tutor logs or ledger; J-01 separately demonstrated in-process retention. Provider retention and external logging policies remain undecided. [Prompts](../../../services/api/src/edu_api/tutor/prompts.py) · [Output validation](../../../services/api/src/edu_api/tutor/validation.py) · [Privacy tests](../../../tests/unit/tutor/test_privacy.py)
- **Deployment.** The pinned production application has no Jude route, OpenAPI is unchanged, and the proposed tutor schema is absent from the application database. Configuration defaults to disabled/mock, and omitted consent and entitlement gates deny access. Environment configuration alone does not mount the router. Future wiring that registers it, supplies affirmative gates or injects a live-capable adapter requires a separate review. No real learner data or live AI endpoint was used. [Application factory](../../../services/api/src/edu_api/main.py) · [Configuration](../../../services/api/src/edu_api/tutor/config.py)

**Merge recommendation.** Return the four high-severity findings to the implementer. Keep independent regression assertions visible, document the exact guarantees for the remaining findings, and re-review a new pinned commit before owner approval. Staff/worker integration, consent/entitlements, erasure orchestration, approved provider terms and bilingual safeguarding review remain separate activation gates. No implementation approval, deployment, migration or benchmarking is part of this review.
