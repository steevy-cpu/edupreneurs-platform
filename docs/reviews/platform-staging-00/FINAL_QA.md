## Findings, ordered by severity

| Severity | Finding and observed evidence | Correction and acceptance criterion |
|---|---|---|
| **High · QA-5** | The supported `make dev-login` and `make token` paths can reach an Auth password update after checking only that the hostname is local. Both tests supplied an unowned loopback destination and intercepted the first write **before transport**. With a stale owner environment and its matching key, these helpers could change a synthetic account on the shared Auth stack. The audited pytest fixture separately verifies its environment. [Login helper](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/dev_login.py#L27) · [Token helper](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/dev_token.py#L33) | Bind each standalone mutating helper to the verified checkout, DB/gateway bindings and the exact environment snapshot it consumes. Both raw entry points must reject an unowned destination before initiating any HTTP operation. |
| **High · QA-2** | The metadata-only auditor passed the release audit with effective `UPDATE(version)` on the migration ledger. The test confirmed the privilege through PostgreSQL, ran the actual gate under the auditor role, and rolled back the grant. It never updated a ledger row. A read-only transaction protects this audit invocation. The overprivileged credential could still change the very evidence it is supposed to attest in another session. [Audit predicate](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/staging_verify.py#L43) | Verify effective table **and column** privileges, including inherited/public access, against the intended reader contract. The exact documented read-only role must pass. An extra write privilege must fail before the ledger is trusted. |
| **Medium · QA-1** | The local guard accepts a container publication on a different host interface if the numeric port matches. Recorded Docker metadata used an interface that does not serve `127.0.0.1`. No socket was opened. This disproves endpoint ownership for host-side clients. It does not establish that the project-scoped CLI reset reached another database. [Binding check](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/disposable.py#L144) | Require the selected address family and loopback endpoint to be covered by each DB/gateway publication. Test loopback, IPv4 wildcard and non-covering interface cases. |
| **Medium · QA-6** | File validation and the application settings loader disagree on case handling. With a differently cased process setting, the local guard accepted the file while the real settings loader selected a different loopback DB port. This was a configuration-only test. Fixtures that pass explicit validated values have a narrower exposure. [Override comparison](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/disposable.py#L111) · [Runtime settings](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/services/api/src/edu_api/config.py) | Validate the same effective settings the caller will use. Reject ambiguous case variants or normalize them consistently and compare the resolved endpoint with the verified snapshot. |
| **Medium · QA-3** | After a transactional revocation of the API’s required catalog SELECT on `app.courses`, PostgreSQL confirmed the login lacked that privilege while **every** shared database-readiness predicate still returned true. The real login identity would be unchanged. This probe measured the predicate directly. [Required grant](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/supabase/migrations/20261121000300_api_role_and_policies.sql#L68) · [Readiness predicate](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/services/api/src/edu_api/db/staging_security.sql) | Check the minimum read privileges for the actual student contract, or add a cheap read-only contract probe under the web login. A missing catalog grant should stop promotion and yield degraded readiness. |
| **Medium · QA-4** | The launcher reached Uvicorn’s single-server boundary with `WEB_CONCURRENCY=1`. At 2, the locked Uvicorn exited with status 3 before starting the server because it received an application object. The bundled Render plan currently defaults to 1. Render documents other plan defaults, so resizing or a configuration override can break startup. [Launcher](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/staging_service.py#L52) · [Render environment defaults](https://render.com/docs/environment-variables) | Enforce the advertised one-worker model explicitly, or implement an importable multiworker factory and update the pool budget. Exercise both environmental values against the real launch configuration. |

## Controls reproduced and limits

**PostgreSQL and restore.** The candidate created a fresh PG17 database in the disposable Supabase cluster, restored the three selected schemas, observed effective TEMP despite a complete ledger, applied the checked-in ACL repair on that copy and passed subsequent checks. Direct TEMP drift and an unreviewed extension were detected. Independent transactional probes also caught inherited TEMP and an unexpected private column read. Two additional restores deliberately lost a version row or acquired incorrect ledger metadata after restore. The ledger check caught the former and the data fingerprint caught the latter. Both failed scratch databases were removed. [Restore implementation](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/restore_drill.py) · [Independent database probes](../../../tests/integration/test_platform_staging_qa.py)

**Migration evidence.** A byte change retaining its migration ID failed the manifest checksum. CI also checks the immutable Git tree prefix, and the operator audit checks the ordered applied version list. The ledger records version IDs. An original source whose ledger already misrepresents executed SQL can agree with its restored copy. The row fingerprint provides no independent attestation of historical SQL execution, sequence positions, index definitions or provider settings. Extension checks compare installed names to an allowlist. Versions, owners, extension schemas and extension-specific grants still need review. The drill uses roles from the same cluster and assumes quiescent writers. It supplies no hosted RTO/RPO measurement. [Migration gate](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/scripts/staging_verify.py) · [SQL allowlist](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/services/api/src/edu_api/db/staging_security.sql#L23)

**Authentication, TLS and pooling.** The suite exercised real local Auth sign-in, protected API requests, wrong identity/token cases, outage handling, pool actor isolation and the database readiness failure path. Independent launcher tests rejected mismatched issuer, JWKS, environment and port before starting a server, and kept the synthetic DSN marker out of parser errors. The staging engine received a certificate-verifying, hostname-checking TLS context with pre-ping and rollback-on-return. This inspects driver arguments; a hosted TLS handshake, pooled-login mapping, TLS trust chain and connection saturation remain untested. In a separate fake-clock experiment the cached public signing key remained usable after a simulated 30-day JWKS outage. JWT expiry is still verified. Decide and document a stale-key/revocation policy before relying on key withdrawal during outages. [JWKS fallback](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/services/api/src/edu_api/auth/jwks.py#L119) · [Engine configuration](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/services/api/src/edu_api/db/session.py#L49)

**CI and secrets.** The existing workflow used read-only repository permissions, a disposable stack, lockfile checks, static analysis, contract regeneration checks and Gitleaks over the introduced history. The restore runs subprocess argument lists, validates the target before connecting and uses a generated scratch DB name for cleanup. The temporary dump contains Auth and app bytes and stays on the runner. The reviewed template has no embedded credentials, sits under an example path and disables automatic redeploys. Importing it manually can still initiate a billable first deployment. The scan, synthetic error probes and lack of deployment hooks do not establish provider log retention, secret rotation or host isolation. [Workflow](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/.github/workflows/platform-staging-00.yml) · [Inactive example](https://github.com/steevy-cpu/edupreneurs-platform/blob/bf52dd0c779052ac25ec6c4dc209575b0671bfc0/docs/infra/staging-00/examples/render.staging.yaml.example)

**Render readiness and rollback.** Local HTTP smoke covered liveness and DB readiness. The candidate integration suite exercised staging startup rejection and a generic 503 on an unsafe database policy. The independent launcher probe intercepted Uvicorn immediately before serving. A DB-only green probe cannot establish that Auth or a student request succeeds. Render documents that rollback depends on a retained successful artifact, reuses some target settings, handles environment groups separately, and keeps the current compute plan. A rollback rehearsal must include credential rotation, the old binary against the current schema and a subsequent ordinary deploy. Neither a hosted rollback nor Render traffic admission, geographic latency, provider backups or billing was exercised. [Render health checks](https://render.com/docs/health-checks) · [Render rollback semantics](https://render.com/docs/rollbacks)
